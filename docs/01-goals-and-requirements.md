# 1. Цели и требования

## Статус утверждений

- **Факт условия:** до 500 000 комментариев в сутки. Проект фактически выполнен индивидуально Телегиным Даниилом Евгеньевичем; индивидуальный формат допускается по согласованию с преподавателем. Русский текст в MVP — проектное ограничение.
- **Проектное решение:** event-driven архитектура, human-in-the-loop, три маршрута риска.
- **Допущение:** любые численные цели и организационные детали, не данные в условии.

## Проблема и AS-IS

Пользователь публикует комментарий; реактивная модерация начинается после жалобы или ручного просмотра. Единая FIFO-очередь не учитывает тяжесть нарушения. Модератор вручную сопоставляет текст с политикой, принимает решение и при необходимости рассматривает апелляцию. Это создаёт задержку, неравномерную нагрузку и слабую трассируемость.

## Заинтересованные стороны

| Сторона | Интерес | Риск |
|---|---|---|
| Пользователи | Безопасное общение и свобода выражения | Ошибочная блокировка или воздействие вредного контента |
| Модераторы | Приоритетная и объяснимая очередь | Перегрузка, травмирующий контент |
| Trust & Safety / владелец продукта | Соблюдение политики и измеримый эффект | Репутационный и регуляторный ущерб |
| ML/data-команда | Качественные данные и управляемый lifecycle | Drift, bias, утечка данных |
| SRE/безопасность | Надёжность и расследуемость | Сбой, атака, потеря событий |
| Юристы/DPO | Законная и минимальная обработка | Нарушение требований о данных |

## Цели

| ID | Цель | Предлагаемый индикатор |
|---|---|---|
| G1 | Быстро ограничивать потенциально опасный контент | p95 времени до маршрутизации/скрытия |
| G2 | Контролировать ошибочные ограничения | FPR, precision, доля успешных апелляций |
| G3 | Снизить ручную нагрузку | Доля потока, не требующая просмотра |
| G4 | Обеспечить доказуемость решений | Полнота audit events и воспроизводимость версии модели |

## Бизнес-требования

| ID | Требование | Приёмка |
|---|---|---|
| BR-01 | Опасные категории обрабатываются приоритетно | Приоритет отражён в очереди и SLA |
| BR-02 | Автоматические меры обратимы | Есть апелляция и восстановление видимости |
| BR-03 | Решение воспроизводимо | Сохранены policy/model version, score и audit trail |
| BR-04 | Эффект проверяется контролируемым пилотом | Есть контроль, guardrails и критерии остановки |

## Функциональные требования

| ID | Требование |
|---|---|
| FR-01 | Принимать событие создания/изменения комментария идемпотентно. |
| FR-02 | Нормализовать текст, определить язык и сформировать безопасное представление. |
| FR-03 | Возвращать многометочные вероятности, spam score, sentiment и версию модели. |
| FR-04 | Применять версионируемую policy и выбирать `ALLOW`, `REVIEW`, `TEMP_HIDE`. |
| FR-05 | Поддерживать приоритетную очередь, назначение и историю решений модератора. |
| FR-06 | Принимать апелляции и восстанавливать контент при отмене решения. |
| FR-07 | Записывать append-only аудит всех автоматических и ручных действий. |
| FR-08 | Формировать feedback events для разметки и последующего обучения. |
| FR-09 | При сбое модели переходить к правилам/ручной очереди без потери события. |

## Нефункциональные требования

| ID | Проектная цель |
|---|---|
| NFR-01 | Доступность online-контура ≥ 99,9%/месяц. |
| NFR-02 | p95 маршрутизации ≤ 800 мс, p99 ≤ 2 с при 120 RPS. |
| NFR-03 | Потеря подтверждённых событий ≤ 0,001%; повторная доставка допустима при идемпотентности. |
| NFR-04 | Шифрование в передаче и хранении, RBAC, секреты вне кода. |
| NFR-05 | Горизонтальное независимое масштабирование consumers и inference. |
| NFR-06 | Наблюдаемость по request/event ID без текста комментария в обычных логах. |
| NFR-07 | Доступность функции удаления/анонимизации по субъекту данных. |

## Ограничения

- Только русскоязычный текст в MVP; мультимедиа и полноценная мультиязычность вне объёма.
- Тональность не является нарушением и не должна сама запускать санкцию.
- Точный состав запрещённых категорий зависит от политики платформы и юрисдикции.
- Индивидуальное выполнение особенно требует managed-инфраструктуры, минимального числа собственных сервисов и автоматизации эксплуатации.

## Трассируемость

| Цель | Требование | Компонент | Метрика | Проверка пилота |
|---|---|---|---|---|
| G1 | BR-01, FR-03—04 | Inference, Policy Engine, Router | recall, p95 latency | Shadow replay и фаза ограниченной автоматизации |
| G2 | BR-02, FR-06 | Review UI, Appeal Service | precision, FPR, appeal overturn rate | Сравнение с контролем |
| G3 | FR-04—05 | Router, Review Queue | review rate, handling time | A/B по стабильному хешу |
| G4 | BR-03, FR-07 | Registry, Audit Log | audit completeness | Выборочная реконструкция решений |

## Оценка и статус допущений

Допущения ниже подтверждены исполнителем как проектные решения. Они не подменяют измерения пилота и обязательные внешние согласования.

| ID | Допущение | Оценка адекватности и статус |
|---|---|---|
| A-01 | Проект выполнен индивидуально Телегиным Даниилом Евгеньевичем | Факт подтверждён; до сдачи требуется согласование индивидуального формата с преподавателем. |
| A-02 | Пик равен 10× среднего, запас мощности — 2× | Адекватная консервативная sizing-гипотеза при отсутствии почасовой статистики; подтверждено, уточняется нагрузочным тестом. |
| A-03 | Временное скрытие допустимо и обратимо | Адекватно для снижения риска, если это разрешено политикой платформы; подтверждено как проектное решение, policy/legal approval обязательно до production. |
| A-04 | Raw-текст хранится 90 дней | Разумный стартовый срок для разбирательств и переобучения; подтверждено условно, окончательный срок задаёт privacy/legal review. |
| A-05 | Апелляция доступна 30 дней | Адекватный и понятный пользователю продуктовый срок; подтверждено. |
| A-06 | Контроль — 10%, автоматизация — до 10% трафика | Осторожная стартовая доля, сохраняющая контроль; подтверждено, расширение только после guardrails. |
| A-07 | Каждая фаза длится минимум 14 дней | Адекватный календарный минимум; подтверждено при обязательном условии достаточной статистической мощности. |
| A-08 | Категории и пороги утверждает Trust & Safety | Обязательный механизм governance; подтверждено, фактическое утверждение выполняется владельцем политики до запуска. |
