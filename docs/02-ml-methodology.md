# 2. ML-методология

## Постановка задач

Один комментарий может иметь несколько независимых меток. Основная задача — многометочная классификация; spam detection выделен из-за иных сигналов и стоимости ошибки; sentiment — вспомогательная аналитика и не основание для санкции.

| Группа | Метки MVP | Приоритет ошибки |
|---|---|---|
| Опасные | угроза/призыв к насилию, целевая ненависть, сексуальная эксплуатация несовершеннолетних, самоповреждение (кризисный сигнал) | Максимизировать recall, обязательная проверка человеком |
| Токсичность | оскорбление, травля, нецензурная агрессия | Баланс precision/recall |
| Запрещённое | незаконные товары/услуги, раскрытие персональных данных | По политике; высокий риск требует приоритета |
| Спам | массовый спам, мошенническая ссылка, координированная реклама | Высокая precision для авто-действий |
| Тональность | negative, neutral, positive | Только аналитический сигнал |

Финальная таксономия — версия политики, а не неизменная истина. Многозначные и цитируемые высказывания размечаются с контекстом; несогласие или негативная оценка сами по себе не считаются токсичностью.

## Данные и разметка

Источники: исторические комментарии, жалобы, решения и причины модераторов, апелляции, policy version, минимальный контекст ветки и агрегированные антиспам-признаки. Данные очищаются от прямых идентификаторов; доступ к исходному тексту ограничен.

Инструкция разметчика содержит определения, положительные/отрицательные примеры, правила цитирования, иронии, reclaimed speech и недостаточного контекста. Не менее 10% выборки размечают два асессора. Контроль: Cohen's kappa/класс, disagreement review, golden set и регулярная калибровка. Низкое согласие блокирует автоматизацию соответствующего класса.

## Разбиение и качество

- Разбиение по времени: train → validation → test; самый новый период — test.
- Одна ветка, near-duplicate и пользовательская кампания не пересекают split.
- Отдельные slices: редкие классы, новые пользователи, сленг, код-свитчинг, цитаты.
- Дисбаланс: стратифицированная выборка, class weights/focal loss, hard-negative mining; итоговые метрики пересчитываются на естественном распределении.
- Проверки: схема, null/range, дубликаты, leakage, label prevalence, language mix и связь `prediction → final decision`.

## Модели

1. **Правила** для известных ссылок, повторов и обязательных политик.
2. **Baseline:** word/character TF-IDF + one-vs-rest logistic regression; отдельная линейная модель spam.
3. **Кандидат:** дообученный русскоязычный transformer с sigmoid heads; отдельная или совместная голова тональности.
4. Калибровка вероятностей по классу (temperature/isotonic на validation), registry и canary release.

Выбор делается по качеству, калибровке, latency, стоимости, объяснимости и устойчивости, а не только по F1.

## Offline-метрики

По каждому классу: precision, recall, F1, PR-AUC, confusion matrix и calibration error/Brier score. Дополнительно macro-F1 для редких классов, micro-F1 для общего потока и slice-метрики. Accuracy недостаточна: при редком нарушении модель, всегда отвечающая «нет», получает высокую accuracy и нулевой recall.

| Метрика | Бизнес-риск | Проектная гипотеза порога/цели |
|---|---|---|
| Recall опасных классов | Опасный контент останется видимым | ≥ 0,95 на test; нижняя граница CI подтверждается до запуска |
| Precision `TEMP_HIDE` | Допустимая речь временно скрыта | ≥ 0,95 и FPR ≤ 0,5% |
| Recall токсичности | Пропущенная травля | ≥ 0,85 при согласованном precision |
| PR-AUC по классу | Качество при дисбалансе | Не хуже baseline, статистически/практически значимое улучшение |
| ECE | Некорректные пороги риска | ≤ 0,05 либо калибровка повторяется |

## Маршрутизация

Policy Engine использует максимум калиброванного риска с class-specific overrides.

| Маршрут | Рекомендуемое правило-гипотеза | Действие |
|---|---|---|
| `ALLOW` | все policy-risk score < 0,40 и нет жёсткого правила | Оставить видимым; 1% отправить на аудит |
| `REVIEW` | риск 0,40–0,85; низкая уверенность; disagreement моделей | Оставить видимым или ограничить распространение по политике; ручная очередь |
| `TEMP_HIDE` | опасный класс ≥ 0,85 либо детерминированное критическое правило | Временно скрыть; приоритетная проверка |

Порог тональности не участвует в санкциях. Пороги подбираются по cost matrix на validation и подтверждаются на test/pilot; значения не являются результатами эксперимента.

## Online-метрики и связь с бизнесом

| ML/системная метрика | Продуктовая метрика |
|---|---|
| Recall по delayed labels | Доля пропущенных нарушений по жалобам/аудиту |
| Precision/FPR `TEMP_HIDE` | Отмены решений и успешные апелляции |
| Coverage `ALLOW` | Снижение ручного потока |
| Calibration/drift | Стабильность маршрутов и очередей |
| Inference latency/error | Время до ограничения и доля fallback |

## Риски моделирования

- Drift языка и атак обхода: PSI/embedding drift, свежая разметка, adversarial tests.
- Bias по диалектам/группам: slice-аудит при законном и этичном наличии признаков; контрфактуальные тесты.
- Label bias модераторов: двойная разметка, апелляции, blind review.
- Feedback loop: не учить только на автоматически отобранных примерах; сохранять случайный аудит.
- Leakage и memorization: временной split, дедупликация, privacy tests.
- Неопределённость: отправлять человеку, не превращать score в утверждение о намерении пользователя.
